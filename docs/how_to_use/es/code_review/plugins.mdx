## Descripción General

Los plugins te permiten incorporar contexto de negocio externo directamente en el flujo de revisión de Cody. Amplían la comprensión de Cody con datos de herramientas como Jira, para que el feedback y las acciones se mantengan alineados con los procesos de tu equipo.

## Qué Son los Plugins

Los plugins son servidores Model Context Protocol (MCP) curados por Codus. Cada plugin expone capacidades específicas — como obtener tareas o verificar especificaciones — que Cody puede usar mientras colabora contigo en los pull requests.

## Codus MCP

Cada workspace incluye el Codus MCP ya conectado. Agrega adaptadores seguros para cada proveedor de Git soportado — GitHub, GitLab, Bitbucket y Azure DevOps — por lo que nunca necesitas instalar plugins de manipulación de código por separado.

Más allá del control de código fuente, el Codus MCP desbloquea automatizaciones de primera parte:

- Gestionar las reglas de Cody directamente desde un hilo de revisión (crear, editar o eliminar).
- Abrir issues de Cody manualmente cuando necesitas un seguimiento personalizado fuera del flujo automatizado.

## Usar Plugins en Sugerencias

<img src="https://kodus.io/wp-content/uploads/2025/10/comment-mcp.gif" alt="Ejemplo de uso de un plugin en una sugerencia" />


Interactúa con un plugin dentro de una sugerencia de revisión de código mencionando explícitamente a Cody en tu comentario. Una vez invocado, Cody llama al plugin relevante y responde en el mismo hilo.

### Ejemplos de prompts

- `@cody, actualiza esta regla de cody para ignorar archivos de prueba`
- `@cody, mueve esta tarea https://jira.com/task-123 a DONE`

Estos prompts mantienen la discusión en contexto y permiten que los compañeros de equipo sigan la conversación completa dentro del PR.

## Validar Lógica de Negocio

Usa el comando `@cody -v business-logic` cuando quieras que Cody compare un pull request con una especificación. Proporciona el contenido de la especificación en línea o comparte un enlace:

- `@cody -v business-logic https://jira.com/task-123`

Cody obtendrá la especificación referenciada a través del plugin y confirmará si la implementación coincide con el comportamiento documentado.

## Controlar el Acceso

Cody solo ve las herramientas que habilitas para cada workspace. Instala los plugins que importan a tu flujo de trabajo y mantén todo lo demás privado.

## Plugins Personalizados

Trae tus propios servidores MCP cuando necesites capacidades más allá del catálogo curado.

1. Abre el catálogo de plugins dentro de tu workspace y haz clic en **Agregar Plugin Personalizado**.
2. Proporciona los detalles del endpoint:
   - **Nombre del Plugin** (obligatorio) y **Descripción** opcional para ayudar a los compañeros de equipo a entender la integración.
   - **URL del Logo** opcional para un ícono reconocible en el catálogo.
   - La **URL** de MCP que aloja tu servidor junto con el **Protocolo** esperado (HTTP o WebSocket).
   - Cualquier método de **Autorización** requerido o encabezados personalizados para la autenticación.
3. Haz clic en **Crear Plugin** para que esté disponible inmediatamente para Cody dentro del workspace actual.

Los plugins personalizados siguen el mismo modelo de permisos que las integraciones curadas: solo los workspaces donde está instalado el plugin pueden invocarlo, y Cody nunca accede a endpoints que no configures explícitamente.

## Consejos

- Menciona a Cody solo una vez por solicitud para que el plugin correcto se ejecute sin duplicación.
- Mantén los enlaces accesibles para tu workspace; Cody necesita permiso para llegar al recurso de destino a través del plugin.
- Revisa el catálogo de plugins periódicamente — se agregan nuevas integraciones a medida que Codus cura servidores MCP adicionales.
